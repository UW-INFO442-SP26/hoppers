# HuskyPath Personas

## First-Year Student Finding Class

Maya is new to UW and needs to move from a familiar place, like Red Square, to a building she has not visited before.

Needs:
- Quick route setup without an account.
- Clear time and distance estimate.
- Step-by-step directions that match campus landmarks.

How HuskyPath supports this:
- Start and destination selectors keep the route flow simple.
- The map line and route summary update together.
- Building details help confirm the selected destination.

## Student Avoiding Stairs

Jordan wants to avoid stairs when possible because stairs make campus travel slower and harder.

Needs:
- An accessible route option.
- A way to report stair-heavy paths when the route data misses them.
- Building accessibility details.

How HuskyPath supports this:
- Accessible mode asks the route service to penalize steps.
- The report pin flow lets testers flag stairs or blocked paths.
- Building detail cards include accessibility notes.

## Campus Visitor On Mobile

Sam is visiting UW for a meeting and is using a phone while walking through campus.

Needs:
- Touch-friendly controls.
- A layout that works on a small screen.
- Building name, code, and basic amenities.

How HuskyPath supports this:
- Native select controls and buttons work with touch.
- The map, route panels, report form, and MVP page stack on mobile.
- The details panel shows services, hours, and restroom notes.
